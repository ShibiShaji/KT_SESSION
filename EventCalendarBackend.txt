## KT EXPLANATION

### 1. event.controller.ts
Show: `EventController / getEvents()`

Explain:
- The calendar view triggers `GET /events` with query parameters like `page`, `limit=100`, `filterstartDate`, and `filterendDate`.
- The controller extracts the query parameters, builds an `EventModel`, attaches the authenticated user from `req.user`, and invokes the business layer.
- It delegates data retrieval to `EventService.findEventsByPagination()` because business rules and date-window filtering belong in the service layer.

↓

### 2. event.model.ts / common.model.ts
Show: `EventModel` and `PaginationModel`

Explain:
- `EventModel` defines the accepted filtering properties including `filterStartDate`, `filterEndDate`, `status`, and category/mode IDs.
- `PaginationModel` carries pagination metadata (`page`, `limit`, `skip`) to prevent loading unbounded records.
- After binding query arguments into `EventModel`, the validated criteria are passed into `EventService`.

↓

### 3. event.service.ts
Show: `EventService / findEventsByPagination()`

Explain:
- This service handles all calendar query logic, role-based scope checks (e.g., manager filtering), and date overlap rules.
- It constructs a TypeORM query builder against the `sea_events` table with conditions `startDate <= :filterEndDate` AND `endDate >= :filterStartDate`.
- It executes a 2-step retrieval: first getting matching event IDs for precise pagination and total count, then fetching full event relations.

↓

### 4. event.entity.ts / TypeORM Repository
Show: `EventService.repository.createQueryBuilder('event')`

Explain:
- Injects `Repository<Event>` (`@InjectRepository(Event)`) to interact with the database via TypeORM.
- Joins related lookup tables: `eventType`, `eventStatus`, `currentStatus`, and `assignedManager`.
- Executes SQL queries against the database and returns matching entity rows sorted by event date/id.

↓

### 5. DB (SQL Server / sea_events)
Show: SQL Query generated by TypeORM

Explain:
- Runs `SELECT event.* FROM sea_events event WHERE event.is_delete = 0 AND event.event_status_id = 4 AND (event.start_date <= :filterEndDate AND event.end_date >= :filterStartDate)`.
- Filters only active, published events falling within the calendar's current month/week view.
- Returns raw event rows including dates, times (`startTime`, `endTime`), mode (`eventModeId`), and venue details.

↓

### 6. RESPONSE
Show: `EventController / serializeEventsResponse()` and `formatLocalDateTime()`

Explain:
- The service wraps the entity array and pagination count into a standard `ResponseModel`.
- `EventController.serializeEventsResponse()` sanitizes `startDate`, `endDate`, `startTime`, and `endTime` using `formatLocalDateTime()` to prevent timezone shifts across clients.
- The controller returns `{ success: true, data: { data: [...events], total, page, limit } }` back to the client for FullCalendar rendering.

## IMPORTANT SIDE FLOWS

### Side Flow 1 — Date Range Filter (Calendar Navigation)
Trigger: User clicks Next/Prev month or picks date range in UI
→ File: `event.controller.ts`
→ Function: `getEvents(@Query('filterstartDate'), @Query('filterendDate'))`
→ What happens: Controller receives updated date boundaries and passes them into `model.filterStartDate` and `model.filterEndDate`.
→ Next: `EventService.findEventsByPagination()` executes range overlap query (`startDate <= filterEndDate AND endDate >= filterStartDate`) and returns the month's events.

### Side Flow 2 — Event Details Modal Click
Trigger: User clicks an event card on the calendar
→ File: `event.controller.ts`
→ Function: `getEventById(@Param('id') id: number)`
→ What happens: Controller reads event ID from URL param and calls `EventService.findEvents(model)`.
→ Next: Returns full event details with speakers, sessions, and location back to the client modal.

### Side Flow 3 — Create Event
Trigger: Admin / Facility Manager creates a new calendar event
→ File: `event.controller.ts`
→ Function: `createEvent(@Body() body: EventModel)`
→ What happens: Validated payload passes `@Roles(1)` guard and calls `EventService.createOrUpdateEvent(body)`.
→ Next: Event is inserted into `sea_events` table and appears on the calendar.

### Side Flow 4 — Update Event
Trigger: Manager reschedules or edits event details
→ File: `event.controller.ts`
→ Function: `updateEvent(@Param('id') id: number, @Body() body: EventModel)`
→ What happens: Verified by `@Roles(1, 2)` guard and updates existing record via `EventService.createOrUpdateEvent()`.
→ Next: Database updates `startDate`, `endDate`, or `location` and returns updated event model.

### Side Flow 5 — Delete Event (Soft Delete)
Trigger: Manager deletes an event
→ File: `event.controller.ts`
→ Function: `deleteEvent(@Param('id') id: number)`
→ What happens: Controller calls `EventService.deleteEvent(id)`.
→ Next: `EventService` performs soft delete `this.repository.update(id, { isDelete: true })`, excluding it from subsequent calendar queries.

### Side Flow 6 — Authentication & Role Guard
Trigger: Incoming HTTP request without or with JWT header
→ File: `apps/event-api/src/guards/roles.guard.ts`
→ Function: `canActivate(context: ExecutionContext)`
→ What happens: Validates decoded JWT user role against required roles `@Roles(1, 2, 3, 4)`.
→ Next: If unauthorized, throws `ForbiddenException`; if authorized, request proceeds to `EventController`.

### Side Flow 7 — Error Handling
Trigger: Invalid parameters or database query failure
→ File: `event.controller.ts`
→ Function: `try-catch` inside `getEvents()`
→ What happens: Catches any runtime exception, logs the error stack, and returns `{ success: false, message: errorMessage, data: null }`.
→ Next: Client receives structured failure response without server crashing.
