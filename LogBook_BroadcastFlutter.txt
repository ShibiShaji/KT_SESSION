## KT EXPLANATION — LOGBOOK FLOW

### 1. lib/screens/nursery/conversation/logBook.dart
**Show:** `_LogBookState.build()` (lines 189–213, 293–307) & `LogCard.onTap` (lines 370–398)

**Explain:**
- Logbook serves as the central messaging hub between parents and nursery staff per child.
- Watches `activeLogBookProvider` which dynamically branches between parent kids and staff classroom students.
- Tapping a child's card navigates to `ChatDetailScreen` passing `kid` and `isNurseryUser: isStaff`.

↓

### 2. lib/screens/parent/finance/repository/financeRepositoryProvider.dart
**Show:** `LogBookPaginationNotifier._fetchParentPage()` & `_fetchStaffPage()` (lines 110–180)

**Explain:**
- Manages paginated chat threads for both user roles.
- For Parents: fetches enrolled children, then queries `latestConversationProvider` for each child.
- For Staff: queries classroom conversations mapped to `LogBookItem` models.

↓

### 3. lib/screens/nursery/conversation/repository/conversationRepositoryProvider.dart
**Show:** `latestConversationProvider` & `conversationRepositoryProvider`

**Explain:**
- Connects the logbook UI with the backend communication repository.
- Calls `conversationRepository.getConversationsByKid()` with `pageSize: 1` to get the latest preview message, unread status, and timestamp.

↓

### 4. lib/screens/nursery/conversation/repository/conversationRepository.dart
**Show:** `ConversationRepository.getConversationsByKid()` (lines 433–480)

**Explain:**
- Selects endpoint based on user role: `/logbook/getConversationsByKid` for staff, or `/pmslogbook/getConversationsByKid` for parents.
- Executes Dio GET request passing `kidInfoId`, `tagTypeId`, `pageNumber`, and date filters.
- Maps the response JSON array into `List<Conversation>`.

↓

### 5. API
**Show:** `GET /pmslogbook/getConversationsByKid` (PMS) / `GET /logbook/getConversationsByKid` (NMS)

**Explain:**
- Fetches all threaded communication messages exchanged for the given child.
- Returns messages with sender info, timestamp, text, attachments, and broadcast flags.

↓

### 6. lib/screens/nursery/conversation/chatDetailedScreen.dart
**Show:** `ChatDetailScreen.build()` & message rendering

**Explain:**
- Renders the full 1-on-1 message stream between parent and nursery staff.
- Regular messages render as text bubbles; broadcasts automatically render using `BroadcastBubble`.

## KT EXPLANATION — BROADCAST CREATION FLOW (NURSERY STAFF)

### 1. lib/screens/nursery/broadcast/broadcastInitial.dart
**Show:** `_BroadcastInitialState.build()` (lines 280–301) & FAB (lines 586–606)

**Explain:**
- Main broadcast hub for nursery staff with tabs for Principal, Teacher, and Nurse.
- Watches `broadcastPaginationProvider` to display all sent broadcasts with response counters (accepted, rejected, pending).
- Tapping the (+) FloatingActionButton starts the multi-step creation flow (`/broadcast-nursery-list`).

↓

### 2. Multi-Step Target Selection
**Show:** 
- `broadcastNurseryListing.dart` (Select Nursery)
- `broadcastNurseryClass.dart` (Select Classes/Sections)
- `broadcastNurseryStudent.dart` (Select Specific Students)

**Explain:**
- Staff picks recipient target scope (entire nursery, specific classes, or individual students).
- Stores selected IDs in `selectedNurseryIdsProvider`, `selectedSectionsProvider`, and `selectedStudentsProvider`.
- Advances to the final composer screen: `/broadcast-nursery-principal`.

↓

### 3. lib/screens/nursery/broadcast/broadcastNurseryPrincipal.dart
**Show:** `buildConversationRequest()` & `createConversationProvider` (lines 78–113, 303–326)

**Explain:**
- Staff inputs broadcast title, message body, message type (Normal, Consent, Mandatory), and selects sender tab.
- Constructs `ConversationRequest` combining target IDs, tag type, and consent/mandatory flags.
- Calls `createConversationProvider(finalRequest).future` to dispatch the broadcast.

↓

### 4. lib/screens/nursery/conversation/repository/conversationRepository.dart
**Show:** `ConversationRepository.createConversation()` (lines 17–35)

**Explain:**
- Sends a Dio POST request to `${baseUrlPMSProvider}/logbook/createConversation`.
- Passes query parameter `SelAcademicYearId: 3` and the serialized `ConversationRequest` payload.
- Returns `CreateConversationResponse` confirming successful mass broadcast creation.

↓

### 5. API
**Show:** `POST /logbook/createConversation`

**Explain:**
- Generates broadcast conversation records across all selected nurseries, classes, and students.
- Creates individual child conversation log entries so each parent receives the broadcast in their feed.

## KT EXPLANATION — BROADCAST RESPONSE & PARENT CONSENT FLOW

### 1. lib/screens/nursery/conversation/components/broadCastBubble.dart
**Show:** `BroadcastBubble._markAsRead()` (lines 47–109)

**Explain:**
- Broadcast appears directly inside the child's logbook chat feed for the parent.
- If the broadcast type is Consent or Mandatory, it renders "Accept" / "Reject" or "Acknowledge" action buttons.
- When parent taps an action, `_markAsRead(accepted)` builds a `Conversation` payload with `isAccepted: accepted`.

↓

### 2. lib/screens/nursery/conversation/repository/conversationRepositoryProvider.dart
**Show:** `replayConversationParentProvider`

**Explain:**
- Bridges the parent's response to the conversation repository.
- Passes the acknowledgement/consent `Conversation` model to `replayConversationParent()`.

↓

### 3. lib/screens/nursery/conversation/repository/conversationRepository.dart
**Show:** `ConversationRepository.replayConversationParent()` (lines 56–73)

**Explain:**
- Executes Dio POST request to `${baseUrlPMSProvider}/pmslogbook/replayConversationParent`.
- Submits parent response timestamp, acceptance boolean, and child ID.

↓

### 4. API
**Show:** `POST /pmslogbook/replayConversationParent`

**Explain:**
- Updates the parent's consent status (`IsAccepected = true / false`) for the broadcast log entry.
- Records the response in real time for staff analytics.

↓

### 5. lib/screens/parent/communication/broadcastNurseryScreen.dart & broadcastResponse.dart
**Show:** `Broadcastnurseryscreen.build()` (lines 78–103) & `BroadcastResponse._buildStudentMapsFromLogs()`

**Explain:**
- Staff taps any broadcast in `broadcastInitial.dart` to open `Broadcastnurseryscreen`.
- Fetches logs via `getConversationsLogByConversationIdProvider` -> `GET /logbook/getConversationsLogByConversationId`.
- Clicking "See Response" opens `BroadcastResponse` showing categorized lists of Accepted, Rejected, and Pending students.

## IMPORTANT SIDE FLOWS

### 1. Logbook Search & Filtering
`Search student name / Filter by Tag, Class, or Date → logBook.dart → Updates logbookDateRangeProvider / logBookClassFilterProvider → Filtered list updates`

### 2. Staff Floating Action Button to Select Classroom
`Staff taps FAB (+) on Logbook → context.push('/class-room', extra: {'flowType': 'logbook'}) → Selects class and student → Opens ChatDetailScreen`

### 3. Broadcast Filter by Date or Class
`Tap Filter icon on broadcastInitial.dart → FilterBottomSheet → Filter by Class / Date → broadcastPaginationProvider reloads with query params`

### 4. Broadcast Permission Verification
`broadcastInitial.dart → _loadBroadcastCreatePermission() → Checks moduleId 44 (isAllowEdit == 1) → Shows/hides (+) FAB for broadcast creation`

### 5. Parent Mandatory Acknowledgement vs Consent
`Mandatory Broadcast: Single "Acknowledge" button → POST replayConversationParent with isAccepted: true`
`Consent Broadcast: Two buttons ("Accept" / "Reject") → POST replayConversationParent with isAccepted: true or false`
