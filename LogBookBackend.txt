## KT EXPLANATION

### 1. conversation.controller.ts
Show: `ConversationController / getConversationsByKid()`

Explain:
- Receives the HTTP GET request sent by Flutter when opening a student's conversation.
- Extracts `@Query() query` parameters including `kidInfoId`, `tagTypeId`, `fromDate`, `toDate`, and pagination values.
- Passes the parameters directly to `ConversationService`.

↓

### 2. conversation.model.ts
Show: `ConversationModel`

Explain:
- Defines the data structure representing a conversation thread.
- Encapsulates key properties such as `tagTypeId` (Teacher, Principal, Nurse), `isConsent`, `isMandatory`, `isStaff`, and nested `conversationLog`.
- Ensures typed contracts between the NestJS BFF and the upstream backend.

↓

### 3. conversation.service.ts
Show: `ConversationService / getConversationsByKid()`

Explain:
- Contains the service logic for retrieving conversations for a specific child.
- Maps parameters (`KidInfoId`, `TagTypeId`, `FromDate`, `ToDate`) for the upstream API call.
- Executes `this.http.get<ConversationModel[]>('logbook/GetConversationsByKid', params, true)`.

↓

### 4. http.service.ts
Show: `HttpService / get()`

Explain:
- Central HTTP gateway client provided by `packages/http` and registered in `DefaultNMSHttpModules()`.
- Automatically attaches the upstream basic authentication token and tenant headers.
- Dispatches the Axios GET request to the upstream core server (`baseURL: process.env.NMS_API_URL`).

↓

### 5. DB / EXTERNAL API
Show: `GET ${NMS_API_URL}/logbook/GetConversationsByKid`

Explain:
- Upstream core service queries the Oracle database for all messages belonging to the given `kidInfoId`.
- Filters records by `tagTypeId` (Teacher, Nurse, or Principal) and date range.
- Returns the complete list of conversation threads and nested reply logs.

↓

### 6. RESPONSE
Show: `ConversationController / getConversationsByKid()` return response

Explain:
- The response is received from `HttpService`, resolved by `ConversationService`, and returned by the controller.
- The controller returns a typed `Promise<ConversationModel[]>` with HTTP 200.
- Flutter receives the array to render the segmented chat timeline and broadcast bubbles.

## IMPORTANT SIDE FLOWS

### 1. Side Flow — Create Message / Broadcast
Staff composes new message or broadcast
→ `apps/nms-api/src/controllers/conversation.controller.ts`
→ `createConversation()` (`POST /logbook/createConversation`)
→ `ConversationService.createConversation()`
→ `POST ${NMS_API_URL}/logbook/CreateConversation`
→ Upstream creates conversation records for targeted students

### 2. Side Flow — Parent Reply & Consent Acknowledgment
Parent replies or taps Accept / Reject on a broadcast
→ `apps/nms-api/src/controllers/conversation.controller.ts`
→ `replayConversationParent()` (`POST /logbook/replayConversationParent`)
→ `ConversationService.replayConversationParent()`
→ `POST ${NMS_API_URL}/logbook/ReplayConversationParent`
→ Upstream updates parent response (`isAccepected: true/false`) and logs message

### 3. Side Flow — Staff / Admin Reply
Teacher, Nurse, or Admin replies to an ongoing conversation
→ `apps/nms-api/src/controllers/conversation.controller.ts`
→ `replayConversationAdmin()` (`POST /logbook/replayConversationAdmin`)
→ `ConversationService.replayConversationAdmin()`
→ `POST ${NMS_API_URL}/logbook/ReplayConversationAdmin`
→ Upstream appends reply entry to conversation log

### 4. Side Flow — Broadcast Response Tracking
Staff checks who Accepted, Rejected, or is Pending
→ `apps/nms-api/src/controllers/conversation.controller.ts`
→ `getConversationsLogByConversationId()` (`GET /logbook/getConversationsLogByConversationId`)
→ `ConversationService.getConversationsLogByConversationId()`
→ `GET ${NMS_API_URL}/logbook/GetConversationsLogByConversationId`
→ Upstream returns list of parent logs with `isAccepected` status

### 5. Side Flow — Mark Conversation as Viewed
User opens chat screen
→ `apps/nms-api/src/controllers/conversation.controller.ts`
→ `viewConversation()` (`POST /logbook/viewConversation`)
→ `ConversationService.viewConversation()`
→ `POST ${NMS_API_URL}/logbook/ViewConversation`
→ Upstream marks messages as seen and updates badge counts
